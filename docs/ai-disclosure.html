AI tool disclosure

Team SynapX used AI coding assistants while building Waypoint Logistics. This page sets out which tools we used, what we used them for, how we kept control of their output, and what the record can and cannot show.

Covers the repository from 26 September to 4 October 2026 (dev at commit 615e274). Prepared on 4 October 2026 by Devmith Amarasekara with Claude Code, for review by the team. See also the system architecture & data model.

1Declaration

We used three AI coding assistants: Claude Code, OpenAI Codex and Google Antigravity. They helped us write application code, automated tests and documentation.

Team members decided what to build, reviewed what the assistants produced, and committed every change under their own name. Changes reached the shared dev branch through pull requests.

3Where people stayed in control

The team wrote rules that every assistant had to follow. The checkpoints between steps belong to people, and the shared database was off limits to assistants.

4What the commit history shows

Claude Code adds a Co-Authored-By: Claude line to the commits it helps write, but members can remove it. 87 of the 373 commits carry that line. Several team members used Claude Code without keeping it, so the count is a minimum. It does not measure how much Claude Code was used, or by whom.

Codex and Antigravity add no such line in this repository, so the history cannot show their use.

Merge commits are excluded. Counts cover all branches pushed to GitHub.

5Safeguards

  • Written rules for assistantsInstruction files (CLAUDE.md, frontend/AGENTS.md) give assistants the team's frontend rules: build on the shared component library and theme, and use one icon set.
  • Plan before codeThe loader rules require the assistant to show its plan and wait for approval before it changes any code.
  • Own features onlyAn assistant only edits its member's own feature. It must ask before touching another member's files, and flag changes to shared models such as Order.
  • Shared database protectedAssistants must never run migrations, seed scripts or deletes on Neon. The demo seed script refuses any non-local database. Only the DB lead applies migrations.
  • Automated testsBackend changes come with tests: 45 test files with 544 tests. The frontend has its own test files as well.
  • Pull requestsWork reaches the shared dev branch through pull requests: 87 have been merged so far.
  • Designs as the referenceScreens are built from the team's Figma designs, which assistants read through the Figma connector instead of inventing layouts.
  • No secrets in the repositoryEnvironment files with passwords and keys are excluded from git, and the rules forbid committing them.

6How these documents were made

This page and the architecture page were produced with Claude Code (Claude Opus 5.5) on 4 October 2026, in a session run by Devmith Amarasekara.

  • The assistant read the code and the git history.
  • It queried the Neon database structure read-only and changed no data.
  • Every number comes from those sources, and every status flow was traced to the code that sets it.
  • The team supplied the audience, the hosting details and the list of other tools.

Team members should review both pages before submission.

7Limits of this disclosure

  • Commit counts are a minimumSeveral members used Claude Code without keeping its co-author line, and Codex and Antigravity add none, so the history understates AI use.
  • Tools outside the repositoryAI tools used outside the code editor leave no record in the repository.
  • Errors are still possibleTests and review reduce the chance of mistakes in AI-assisted code, but do not remove it.
